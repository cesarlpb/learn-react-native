# Testing

El **testing** es una parte esencial del desarrollo de software para garantizar que nuestra aplicación funcione como se 
espera, tanto en el frontend como en el backend. En una app de React Native que utiliza Supabase, el testing puede 
separarse en dos partes principales: **frontend** y **backend**. Además, los puntos de integración entre ambas partes
también pueden probarse.

---

## 1. Testing en el Frontend (React Native)

El objetivo del testing frontend es garantizar que la interfaz de usuario y las interacciones funcionen correctamente.
En este tipo de tests, el objetivo es verificar que los componentes de UI se renderizan de forma correcta, que los datos aparecen
en el formato adecuado, que no hay cargas innecesarias, etc.

Es importante tener en cuenta que el objetivo no es comprobar cada uno de los elementos del front-end o cada uno de los 
botones que coloquemos, ya que algo así sería demasiado cargante en tiempo. El objetivo es asegurarnos de que los elementos 
clave de las interfaces de usuario permiten el uso correcto de la app.

> En el desarrollo siempre hay un equilibrio entre recursos disponibles (tiempo, personas, conocimiento...) y las funcionalidades que queremos implementar.

En general, no sería productivo intentar probar (hacer un test para) cada uno de los elementos de nuestra app. Tampoco 
es necesario siempre que existan verificaciones adicionales, nuestras o por el equipo de QA, en el despliegue.

### Tipos de Testing

1. **Pruebas unitarias**

   - Verifican el funcionamiento de componentes individuales de la UI y funciones específicas.
   - Se utilizan herramientas como **Jest** (integrado en React Native) y **React Native Testing Library** para simular interacciones y validar estados.

2. **Pruebas de integración**

   - Aseguran que diferentes componentes interactúan correctamente entre sí.
   - Ejemplo: Probar que el formulario `TaskForm` actualiza correctamente la lista de tareas al guardar un nuevo registro.

3. **Pruebas de snapshot**

   - Garantizan que la UI no haya cambiado inesperadamente.
   - Ideal para verificar que los componentes visuales, como listas o botones, mantienen su diseño.

### Implementación

- **Herramientas**: 
  
  - **Jest**: Para pruebas unitarias e integración.
  - **React Native Testing Library**: Para simular interacciones de usuario.
  
- **Ejemplo de prueba unitaria para el componente TaskForm**:

  ```javascript
  import React from 'react';
  import { render, fireEvent } from '@testing-library/react-native';
  import TaskForm from '@/crud/TaskForm';

  test('El formulario guarda los datos correctamente', () => {
    const onSaveMock = jest.fn();
    const { getByPlaceholderText, getByText } = render(<TaskForm onSave={onSaveMock} onCancel={() => {}} />);
    
    fireEvent.changeText(getByPlaceholderText('Título'), 'Tarea de prueba');
    fireEvent.changeText(getByPlaceholderText('Descripción'), 'Descripción de prueba');
    fireEvent.press(getByText('Guardar'));
    
    expect(onSaveMock).toHaveBeenCalledWith({
      title: 'Tarea de prueba',
      description: 'Descripción de prueba',
    });
  });
  ```

- **Prueba de integración para Supabase**:
  Mockea el cliente de Supabase para simular las respuestas de la API y verifica que las funciones de frontend respondan correctamente.
  
  Los mocks (responses y objetos) que replican el formato de las consultas reales al backend se pueden hacer en un formato simple
  como REST con JSON. También, hay librerías que ayudan a mockear datos o podemos - si es posible - crear nuestros propios mocks
  a medida.

## 2. Testing en el Backend (Supabase)

Supabase proporciona servicios de backend como autenticación, base de datos y almacenamiento. El testing del backend asegura que estas funcionalidades operen como se espera.

### Tipos de Testing

1. **Pruebas unitarias**

   - Verifican funciones individuales de Supabase (como inserciones, actualizaciones o borrados).
   - Ejemplo: test de insert en una tabla 

2. **Pruebas de integración**

   - Aseguran que las operaciones del backend interactúan correctamente con el frontend y que los permisos (políticas RLS) funcionan correctamente.

3. **Pruebas de seguridad**

   - Valida que solo los usuarios autenticados puedan realizar acciones específicas.

4. **Pruebas de performance**

   - Evalúan cómo responde el backend a múltiples peticiones simultáneas.

### Implementación

- **Herramientas**:
  - **Postman** o **Thunder Client**: Para probar endpoints directamente.
  - **Supabase CLI**: Para ejecutar migraciones y pruebas locales en un entorno controlado.
  - **Jest** (en un entorno Node.js): Para probar consultas a la base de datos.

- **Ejemplo de prueba unitaria para Supabase**:
  
  ```javascript
  import { createClient } from '@supabase/supabase-js';

  const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_KEY);

  test('Inserta una tarea correctamente', async () => {
    const { data, error } = await supabase
      .from('tasks')
      .insert({ title: 'Prueba', description: 'Descripción de prueba' });

    expect(error).toBeNull();
    expect(data).toHaveLength(1);
    expect(data[0].title).toBe('Prueba');
  });
  ```

- **Pruebas de políticas de seguridad (RLS)**:
  
  Usa un usuario autenticado para verificar que solo puede ver o editar sus propios datos.

## **3. Cómo Integrar Testing en una App

1. **Configurar un entorno de pruebas**

   - Usa entornos de desarrollo y pruebas separados.
   - Configura variables de entorno específicas para pruebas (como una base de datos de prueba).

2. **Simulación del cliente de Supabase**

   - Mockea el cliente de Supabase en el frontend para evitar realizar peticiones reales durante las pruebas.

3. **Pruebas E2E (End-to-End)**

   - Usa herramientas como **Detox** (para React Native) para probar la app de extremo a extremo.
   - Verifica que los usuarios puedan registrarse, iniciar sesión, subir archivos y ver sus datos.

4. **Automatización**

   - Configura pipelines de CI/CD (como GitHub Actions o CircleCI) para ejecutar las pruebas automáticamente en cada push o merge.

## **Beneficios del Testing**

En general, los tests son una herramientas más en el repertorio de un programador o equipo de desarrollo para comprobar de forma 
automatizada que ciertas partes de nuestra app funcionan correctamente o de forma esperada.

Esto es especialmente útil cuando integramos una nueva funcionalidad, durante el desarrollo, mientras debugeamos errores, etc.

- **Detección temprana de errores**: Permite identificar problemas antes de que lleguen al usuario final.
- **Confianza en los cambios**: Refactorizar o añadir funcionalidades es más seguro.
- **Mejor mantenimiento**: Facilita la colaboración y reduce el riesgo de introducir errores en el futuro.
